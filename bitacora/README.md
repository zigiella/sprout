# Bitacora de Sprout

Diario del proyecto. Todo el equipo escribe aqui.

## Para que sirve

- Guardar decisiones y el **porque** detras de ellas
- Dejar rastro de lo aprendido (para que otro miembro no repita tropiezos)
- Servir de insumo al writeup final (memoria del proyecto)
- Actuar como "punto de entrada" cuando alguien se incorpora tarde al equipo

## Como se nombra una entrada

```
YYYY-MM-DD_<tema-corto>_<autor>.md
```

Ejemplos reales:
- `2026-04-15_kickoff_cambium.md`
- `2026-04-18_jetson-primer-flash_especialista.md`
- `2026-04-22_pollen-sync-ble-funcionando_ana.md`
- `2026-04-25_dataset-finetune-primeros-50_bea.md`

## Plantilla de entrada

```markdown
# <Titulo breve>

**Fecha:** 2026-MM-DD
**Autor:** <nombre>
**Area:** <Rhizome / Pollen / Meristem / Finetune / Video / Writeup / Research / Hardware / General>
**Tipo:** <Decision / Avance / Bloqueo / Aprendizaje / Pregunta>

## Contexto
Que situacion motivo esta entrada.

## Que hicimos / decidimos
Lo concreto. Sin rodeos.

## Por que
El razonamiento. Esto es lo que vale mas en 2 semanas.

## Que queda pendiente
- [ ] accion 1
- [ ] accion 2

## Enlaces
- [doc relevante](../docs/XX.md)
- [commit](...)
- [issue](...)
```

## Reglas cortas

1. Si una decision se discute mas de 10 minutos, merece entrada
2. Mejor muchas entradas cortas que una larga al final de la semana
3. Si bloqueas a otra persona, escribe entrada tipo "Bloqueo" con la causa y lo que necesitas
4. Los "aprendizajes" (lo que salio mal y como se resolvio) son oro para el writeup
